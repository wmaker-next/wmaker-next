Window Maker IPC protocol
=========================

Transport: AF_UNIX SOCK_STREAM, one listening socket per managed X
screen, path $XDG_RUNTIME_DIR/wmaker/ipc.<display-key> (or
/tmp/wmaker-<uid>/ipc.<display-key> when XDG_RUNTIME_DIR is unset).
<display-key> is the X display name with a screen suffix appended if
absent and every byte outside [A-Za-z0-9] mapped to '_', so :0 and
:0.0 both resolve to "_0_0". Clients may override the path with the
WMAKER_IPC_SOCKET environment variable, the server ignores that
variable when choosing where to bind.

Wire header (16 bytes, native byte order):

    offset 0   uint8_t  magic[8] = "wmaker0\n"
    offset 8   uint32_t length     payload bytes following the header
    offset 12  uint32_t type       request/reply id, or (1u<<31)|n for events

The server caps length at 1 MiB and drops the connection on a frame
that exceeds it or whose magic does not match.

Every non-empty payload is a textual property-list description as
produced by WMGetPropListDescription() and accepted by
WMCreatePropListFromDescription(). Receivers append a NUL after the
length-prefixed payload before parsing and reject embedded NUL bytes.

Request types
-------------
    0  COMMAND         payload: ((verb, arg, ...), ...)
                       reply:   {success=YES|NO; error="...";}
                                or an array of these when more than one
                                command was sent
    1  SUBSCRIBE       payload: ("workspace", "tick", ...)
                       reply:   {success=YES;}
                                followed immediately by a tick event
                                with first=YES when "tick" was named
    2  GET_WORKSPACES  reply:   ({name="..."; index=N; current=YES|NO;}, ...)
    3  GET_WINDOWS     reply:   ({id="0x..."; class="..."; instance="...";
                                  title="..."; workspace=N;}, ...)
    4  GET_VERSION     reply:   {version="..."; display="..."; screen=N;
                                 pid=N; socket="...";}
    5  SEND_TICK       payload: a single proplist string
                       reply:   {success=YES;}
                                a tick event with first=NO carrying the
                                decoded string is broadcast first. The
                                first tick after a clipboard keybinding
                                key press also carries keyed=YES
    6  GET_WINDOW_TREE reply:   {screen=N; version="...";
                                 workspace_count=N; current_workspace=N;
                                 window_count=N;
                                 applications=({
                                   main_window="0x..."; hidden=YES|NO;
                                   appicon={docked=YES|NO; dock="dock"|
                                     "clip"|"drawer"; slot=N; edge=
                                     "left"|"right"|"top"|"bottom";
                                     running=YES|NO; launching=YES|NO;
                                     omnipresent=YES|NO;};
                                   windows=({
                                     id="0x..."; frame="0x..."; pid=N;
                                     class="..."; instance="...";
                                     role="..."; machine="...";
                                     title="..."; types=("...", ...);
                                     geometry={x=N; y=N; width=N;
                                     height=N;};
                                     workspace=N; workspaces=(N, ...);
                                     layer=N; stacking=N;
                                     transient_for="0x...";
                                     group_leader="0x...";
                                     client_leader="0x...";
                                     tab_group={id=N; index=N;
                                     active=YES|NO; size=N;};
                                     creation_id=N;
                                     state={focused=YES|NO; ...};},
                                     ...);}, ...);}
                                Every window appears in exactly one
                                applications entry, leaderless windows
                                under a synthetic entry whose
                                main_window is the window's own id.
                                frame, pid, transient_for, group_leader,
                                client_leader and tab_group are omitted
                                when absent. stacking is the index
                                within the window's layer, topmost
                                first. state carries the bools focused,
                                semi_focused, mapped, miniaturized,
                                hidden, shaded, fullscreen, tiled,
                                urgent, dockapp, gnustep, omnipresent,
                                skip_window_list, skip_switch_panel,
                                modal, demands_attention plus a
                                maximized array decoded from the
                                maximize axes. When the reply would
                                exceed the 1 MiB payload cap the server
                                answers {error="..."; window_count=N;}
                                instead of dropping the connection.

Event types (type field = (1u<<31) | id)
----------------------------------------
    0  workspace   {change="focus"|"create"|"destroy"|"rename";
                    index=N; name="...";}
    1  window      {change="manage"|"unmanage"|"focus"|"title"; id="0x...";}
    2  shutdown    {change="exit"|"restart";}
    3  child_exit  {pid=N; status=N; signal=N; wait_status=N;
                    source="dock"|"menu"|"helper"|"unknown"; slot=N;}
    4  dialog      {kind="message"|"input"|"crash"; title="..."; text="...";}
    5  tick        {first=YES|NO; payload="..."; keyed=YES|NO;}
    6  screenshot  {path="..."; mode="screen"|"window"|"partial";
                    screen=N; workspace=N;}
    7  display_power
                   {state="on"|"off"; source="ipc"|"randr"|"screensaver";}
    8  sound       {event="shade"|"unshade"|"maximize"|"unmaximize"|
                   "iconify"|"deiconify"|"hide"|"unhide"|"appstart"|
                   "appexit"|"dock"|"undock"|"kaboom"|"startup"|
                   "shutdown"|"workspace"|"screenshot"|"lock";
                   screen=N; workspace=N;}

workspace, window, screenshot and sound are screen-scoped, the rest are process-scoped.

display_power is emitted on every actual transition of the global
display_off flag regardless of source. The DisplayOffCommand and
DisplayOnCommand defaults hooks fire only for the randr and
screensaver sources so a scripted `display-power off` does not
recursively launch the configured locker.

Command verbs (request type 0)
------------------------------
While a window cycle is open, reconfigure, info, get-keybinds and
queries remain available. Other commands return an error until the
cycle ends.

    reconfigure
    restart [WM]
    exit
    kill-session
    workspace next|prev|last|N
            next and prev honor the SkipEmptyWorkspaces option and skip
            workspaces holding no non-omnipresent windows. last and N
            are explicit targets and are never filtered
    window-workspace XID +N|-N|N
            move (N), add (+N) or remove (-N) the window's workspace
            membership; N is a 0-based workspace index
    set-layout LAYOUT [workspace N] [master_count N] [master_ratio F]
            switch workspace N (current by default) to LAYOUT, which is
            one of float, tile, tileh, grid, monocle (case-insensitive);
            optional master_count and master_ratio tune the tiling
            parameters of the same workspace. master_ratio must parse
            fully as a finite number with '.' as the decimal separator,
            otherwise the request is rejected
    set-viewport X Y
            pan the current floating workspace so its top-left world
            coordinate is (X, Y). Has no effect on a tiled workspace or
            when EnableVirtualDesktop is NO; the request is clamped to
            the workspace's finite desktop extent
            ([vdesk_x, vdesk_x + vdesk_w - scr_width] and the analogous
            Y range)
    dock-launch SLOT
            launch the docked application at slot SLOT. The slot is the
            dock's along-axis index: the Y cell of the main tile while
            the dock sits on a vertical edge (left or right) and the X
            cell once it is pinned to the top or the bottom. The same
            along-axis index is reported in the child_exit event and in
            the appicon dict of get-window-tree, whose edge field
            (left, right, top or bottom) tells which axis the slot
            counts on
    workspace-new [count]
            create count (default 1) new workspaces
    workspace-delete N
            delete workspace N (0-based index; 0 is the first
            workspace and can never be deleted). Rejected when some
            non-omnipresent window has N as its only workspace;
            windows spanning several workspaces are compacted instead
    action NAME [XID]
            run the key-binding action NAME on the focused window, or on
            XID when given. NAME is a key-binding action name from the
            `info' actions list, either the short form (NextWorkspace) or
            the config key (NextWorkspaceKey). The Hide, HideOthers and
            Close actions target XID even when that window is not focused
            or not on the current workspace. Actions that execute a
            configured shell command (LockScreen, Clipboard) run with
            window-manager privileges
    display-power on|off
    play-sound EVENT
            emit a sound event on the IPC stream; EVENT is one of
            shade, unshade, maximize, unmaximize, iconify, deiconify,
            hide, unhide, appstart, appexit, dock, undock, kaboom,
            startup, shutdown, workspace, screenshot, lock.
            Requires the wmsoundd daemon to be subscribed to
            produce audio; the verb itself only emits the event
    info
            reply carries the usual version fields plus an `actions'
            array listing every action name that `action' accepts
    get-keybinds [all]
            reply carries a `keybinds' array describing the active
            key bindings. By default only bound actions are listed; `all'
            also includes unbound rows. Each row is a dictionary with
            `action' (the short name `action' accepts), `config_key' (the
            schema key for config-file round trips), `spec' (the raw
            config string, locale- and XKB-independent), `category' (the
            group heading used by the shortcuts panel), `description' (a
            human-readable summary) and `bound' (YES or NO). A bound row
            also carries `binding', the rendered display label; an unbound
            row has spec="None" and no `binding' key

Window-manager actions are reached through `action'. Verbs listed above
that duplicate an action stay only while they carry a capability it
cannot express; the MoveToEdge, GrowToEdge, ShrinkToEdge, ShowAll,
ArrangeIcons, Hide, HideOthers and Close actions replaced their former
verbs.

An unknown verb yields {success=NO; error="unknown command '...'";}
and the connection stays open. An unknown `action' name yields
{success=NO; error="unknown action";}.
